## 目标

用户要的不是 ComfyUI 这个图像生成产品，也不是把它跑起来拿来画图。用户看中的是 **画布**：像原生 Comfy 一样，通过拖出或创建节点来编排、控制一条流程。

下文把 ComfyUI 简称为 **comfy**。产品名是 **DrawUI**。

最终产品是一个空的流程画布，并且能看见流程正在往前走：

- 画布上可以创建节点、拖拽、连线。
- 节点来自一套节点框架，框架里当时装的是用户自己的流程节点。
- 后端只负责把这个画布跑起来，并按图执行流程。
- 运行时画布标出当前走到哪个节点。
- 爬虫是这种流程里的一条。图像和视频生成不在产品里。

节点在库里的地位相同。一个节点可以有一个分组和若干标签。分组是节点库顶部的标签页，点开看到这一组。组里用分割线按标签切开。没有分组或标签的归到「其他」。另有一个「全部节点」页，展示同一份列表里的全部节点。这份列表来自 `/object_info` 加上前端自己注入的系统节点，不另向后端要一份分组清单。

个人使用保持 Nodes 2.0（设置项 `Comfy.VueNodes.Enabled`）。节点输入是页面上的真实输入框。图、连线、保存和 `/prompt` 与经典画布相同。

节点专属界面由这个节点自己打开。例如双击 SQLite 节点打开查询页，看表和执行 SQL 用单独接口，不走 `/prompt`。节点的输入输出 schema 不会生成这块界面。

## 保留

保留两块能力，外加让它们能启动的最小后端。

1. **前端画布。** 节点图的交互：空白画布、从菜单或拖拽创建节点、移动、连线、选择、保存图。外观和操作保持 comfy 原生画布。源码在 `DrawUI_frontend`。
2. **节点框架。** 保留「一个节点如何被声明、注册、展示、连线、执行」的机制。节点类上的 schema（输入、输出、类型、分类）、注册表、`/object_info` 把 schema 交给前端、图的 JSON、按图执行。这部分在 `DrawUI`。
3. **最小后端。** 静态资源、画布启动时必须命中的接口、图的提交与执行。没有这块，画布打不开，流程也无法跑。

原生节点不保留。`KSampler`、`CheckpointLoader`、`CLIPTextEncode`、VAE、ControlNet，以及 `comfy_extras/`、`comfy_api_nodes/` 里的模型节点，都是要删的节点内容。留下的是登记和执行它们的那套框架。

## 删除

除画布、节点框架、最小后端以外，都删除。优先删除这些：

- PyTorch 及整条推理依赖：`torch`、`torchvision`、`torchsde`、`transformers`、`safetensors`、`comfy-aimdo`、`comfy-kitchen`，以及 `requirements.txt` 里其余模型相关包。
- `comfy/` 下的模型、采样、显存、权重加载。
- `nodes.py` 里的原生节点实现，以及 `NODE_CLASS_MAPPINGS` 里这些原生条目。注册函数本身先留着。
- `comfy_extras/`、`comfy_api_nodes/`、`models/`、采样与推理测试。
- 云端、合作方 API 节点、模型管理、资源库、上传图片这一类图像产品能力。画布启动如果还调用它们，先改成空实现或从启动路径拿掉，再删实现。

删除时保持进程能启动、画布能打开、节点框架还能注册新节点。禁止先把仓库砍到无法 import。

`/Users/tal/coding/cursor/ComfyUI` 是迁出前的后端副本。交接已离开那里。后续改动只发生在上面两个 fork。

画布源码在 `DrawUI_frontend`。`DrawUI` 运行时仍从 pip 包提供页面：`requirements.txt` 锁着 `comfyui-frontend-package==1.59.1`，由 `app/frontend_management.py` 定位包内 `static/`，`server.py` 把它挂到 `/`。本地前端仓库是 `1.61.2`，和这个锁版本不一致。清理代码时要决定后端改托管本地构建，还是继续用 pip 包。在接线完成前，改 `DrawUI_frontend` 不会自动出现在 `DrawUI` 打开的页面上。

节点框架在 `DrawUI`，分两代，加载入口都在 `nodes.py` 的 `load_custom_node`：

- V1：模块导出 `NODE_CLASS_MAPPINGS`。类上有 `INPUT_TYPES`、`RETURN_TYPES`、`FUNCTION`、`CATEGORY`。
- V3：模块导出 `comfy_entrypoint`，节点继承 `comfy_api.latest` 的 `io.ComfyNode`，用 `define_schema` 描述输入输出。示例在 `custom_nodes/example_node.py.example`。

注册结果进入 `nodes.NODE_CLASS_MAPPINGS`。前端通过 `server.py` 的 `GET /object_info` 读取。用户在画布上运行时，图提交到 `POST /prompt`。原版由 `execution.py` 的 `PromptExecutor` 按依赖执行，这个文件 import 了 `torch` 和模型管理。现在听端口的是 Go，不调用它。削 Python 树时这里要先解开，再谈删除 `comfy/`。

节点在画布上的位置写在工作流 JSON 的 `pos` 里。打开图时按这个坐标放回去，粘贴时再按鼠标平移。`/prompt` 不带坐标。

`server.py` 里画布可能依赖的路由包括：`/`、`/ws`、`/object_info`、`/object_info/{node_class}`、`/prompt`、`/queue`、`/history`、`/interrupt`、`/system_stats`、`/features`、`/extensions`、`/default_workflow`，以及用户设置相关路由（在 `app/user_manager.py`）。`/models`、`/embeddings`、`/upload/image`、`/view` 属于图像产品，默认删除；若前端启动必调，改成空响应后再删实现。

## 现状

- 工作区是 `DrawUI` + `DrawUI_frontend`。
- 画布后端是 Go 单文件：`DrawUI/main.go`（Gin，模块 `drawui`）。`go run .` 听 `:8188`。分支 `cursor/go-canvas-backend`。
- 它实现前端启动和跑图要用的协议：`/api/object_info`、`/api/system_stats`、`/api/users`、`/api/settings`、`/api/jobs`、`/api/prompt`、`/ws`，以及 userdata。节点是 `DrawText`、`DrawNumber`、`DrawJoin`、`DrawShow`。
- Go 执行器是 `runPrompt` 和 `executionOrder`：从没有下游的节点往回收集，每个节点调用一次，交出一个值。够这四个节点跑。通道、逐条发送、工人池都还没有，写在 v0.0.1。
- 原版执行器仍在 `execution.py`。Go 不调用它。Python 树还在，没有删。
- 走到哪的描边前端已经会画，认的是 WebSocket 的 `progress_state`。Go 只发 `executing` 和 `executed`，描边不看这两条，所以现在看不见高亮从上游移到下游。
- 控制台还不是日志流。Go 只有空的 `/internal/logs/raw`，没有订阅，也没有 `logs` 帧。
- 前端开发服务器是 `DrawUI_frontend` 里的 `pnpm dev`，请求代理到 `127.0.0.1:8188`。依赖已安装。
- 前端工作区里已改、尚未提交：去掉右上角登录和「在 ComfyUI Cloud 上运行」；去掉左侧资产、模型、说明；节点库改成上面的分组和标签。Go 的四个节点还没填 `group` 和 `tags`，所以落在「其他」。
- 插件语言还没定。节点若都用 Python，一个讲画布协议并用 `importlib` 加载插件的 Python 服务更直接。不用 Go 标准库的 `plugin.Open`。没选定之前，`main.go` 继续当协议参考，不重写。
